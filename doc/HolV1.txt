Hol V1: bytecode compiler and native interpreter
==============================================

Scope
-----
V1 now executes the existing Hol BETA language through a C search engine,
including higher-order terms. It does not fall back to BETA's interpreter.
The LGS/PGS-generated frontend, type checker, module loader and surface language
are shared with BETA. The default `Hol` command continues to select BETA.

The C engine implements beta/eta normalization, scope-aware higher-order
pattern unification, delayed disagreements, polymorphic terms, pi and sigma,
dynamic hypotheses, multi-head clauses, ordered search, backtracking and cut.
It handles arbitrary-size decimal naturals, open successor terms and wildcards.
Arithmetic, Presburger reasoning, input/output and debugger commands are host
services: Haskell performs those operations when C yields a service request.
The search, bindings and choice points stay in C throughout. Existing BETA
arithmetic semantics and residual constraints are preserved.

Usage
-----
Start ppap, then select either:

    V1 --test --strict
    Hol --v1 --test --strict

Enter a .hol module path and queries as in BETA. `--strict` remains accepted
for existing scripts; both modes now use only V1 execution. Debugging, :show,
:assign and reload are available through the usual source REPL.
`--general` explicitly selects the full engine, including when emitting an
artifact, and is retained across reload. Replay follows the saved format;
emit with --general first, then use --run-bytecode without --general.

    bash example/einstein-v1.sh

The script requests an optimized Haskell build and runs the full Einstein
answer search. C is compiled with -O3. Build time must be measured separately;
a warm script measurement includes Cabal's up-to-date check. The original
example/einstein.sh still runs BETA.

`V1 --dump-bytecode` prints the compiled program. To save a query, select:

    V1 --test --emit-bytecode=answer.hbc

Load a module and enter a query. Each successfully compiled query replaces
answer.hbc and then executes it. Replay enumerates all answers without source:

    V1 --test --run-bytecode=answer.hbc

The artifact contains compiled templates/instructions, symbols, types, query
identities and annotations, not .hol source. Answer projection is shared with
the REPL, including existential constraints. Replay uses standard notation;
module-specific notation declarations are not stored. Its debugger interaction
supports stepping and :d; use the source REPL for the complete command UI.
The experimental .hbc format has explicit versions and validates references,
metadata, identities and closed de Bruijn indices before execution.

Two native code formats
-----------------------
The first-order compiler and version 1 VM remain as an optimized path for
ordinary predicate/constructor queries. The REPL selects version 2 whenever
the lowered program needs higher-order operations, services, unresolved types
or debugging. Before selecting a backend, it specializes provable closed
predicate aliases and checks every reachable clause for first-order support.
Both paths execute C code. The general embedding API always uses version 2,
so callbacks can assign variables or enable debugging during a search.

Version 1 has RETURN, FAIL, CALL, UNIFY, CHOICE and CUT instructions, fresh
clause environments, a trail, continuations and choice points. Its details are
in src/Hol/V1/Bytecode.hs and src/X/machine.h. Older .hbc files still execute.
Clause heads are matched directly against existing goal terms; only a subtree
assigned to an unbound goal variable needs materialization. Internal unbound
variables link to the older representative. Initial query slots retain fresh
representatives so answer projection still reports explicit alias bindings.
Structure bindings retain occurs checks, and every binding is trailed.
Clause slots start empty. A head variable's first occurrence captures the
existing goal term directly, and later occurrences unify against that capture.
Subtree materialization creates variables as needed. After a head succeeds,
remaining empty slots receive fresh variables before body execution: no body
choice can restore a heap checkpoint while leaving an environment slot pointing
into the reclaimed heap. Query slots are allocated eagerly as before.

The version 1 artifact loader reads the emitted decimal word table directly
with Int64 bounds checks. Other previously accepted Read notation uses a
bounded fallback. Both paths retain the full bytecode and metadata validator;
this changes neither the saved format nor the compiler's instruction set.
Both artifact formats also read machine-sized metadata integers through
Integer and reject values outside the destination type before conversion.
This includes nested identities, type variables, source positions and numeric
tags. Natural literals and Integer-valued Presburger fields retain arbitrary
precision. Overflow cannot wrap a saved index or identity into a valid value.

Version 2 uses a compact executable term graph. Its signed 64-bit word header:

    magic=0x484f4c31, version=2, termCount, symbolCount, factCount,
    querySlotCount, queryRoot, metadataCount

Sections follow in this order:

    query slots: [isType, metadata]
    symbol roles: one word per symbol
    term templates: [tag, a, b, reserved=0, reserved=0, metadata]
    facts: [predicateSymbol or -1, templateRoot]
    natural literal payload: decimal ASCII words

Template tags are VAR, CONST, APP, INDEX, LAM, NAT and WILDCARD (0 through 6).
APP/LAM children refer to earlier templates. The native EXEC loop interprets
logical roles and predicate calls over instantiated graphs. Quantifier scopes,
local clauses and continuations are native state, not Haskell AST evaluation.
src/X/higher_machine.h and src/X/term.h specify the C ABI and prefix term wire.

General search and host services
-------------------------------
Version 2 indexes global facts by their dense predicate-symbol IDs. Each call
merges its symbol chain with the dynamically classified (-1) chain in original
source order. Local hypotheses retain their lexical order; a conservative
rigid-head hint skips unrelated heads before instantiation. Flexible,
computational or unrecognized heads still take the ordinary matching path.
This local filter avoids unnecessary instantiation but still scans the local
hypothesis chain.

Ordinary calls search global clauses before local hypotheses. Equality keeps
its distinct local-first policy: once a local head matches, failure of its
body does not enable the arithmetic/global fallback. Choices are omitted only
when the remaining search phases have no candidate. Cut barriers, snapshots
and answer order retain these rules. Equality still uses its host decision
service and ordered clause search; it is not replaced by unconditional native
unification.

A candidate is excluded without a trial when its head is certain not to match:
the clause has the literal shape `pi x\ ... head :- body`, the call is a rigid
application, and either the two predicates differ or some argument pair has
different rigid heads (two distinct ordinary constants or nominals). Naturals,
successor terms, opaque formulas, logical operators, flexible terms and
lambdas never exclude a clause, so the unifier still decides every other case. Excluded candidates are skipped before
the current one is tried, in the state of the search checkpoint; a call whose
remaining candidates are all excluded leaves no choice point. Each skipped
candidate consumes the scheduler batch like a failed trial. A clause of the
literal shape with at most 32 leading binders receives all its variables in
one instantiation of its head, and its body is instantiated only after the
head has unified. Any other clause keeps the binder-by-binder path. Identities are created in the same
order as before, but a skipped trial no longer consumes any.

A host stop exports only what its reply can consult:

    antecedent of `=>`            the event term
    equality without arithmetic   the event terms
    other service request         event terms and disagreements, while the
                                  host holds no constraint and no premise
    answer                        query variables with their values, while
                                  the host holds no constraint and no
                                  disagreement is pending
    debugger stop                 the complete state and frames

Every remaining stop exports the complete variable-binding state, the pending
disagreements and the compact declarations of pending frames, as before: a
stop with a host constraint or premise token, a SETTLE event, a stop while
debugging, and any stop in which a decoded variable or nominal has a type that
the complete state could decide differently (a type variable, a type that
mentions a clause type variable, or a variable without a recorded type). The
reduced stops therefore see the same labels, types and values for every
identity they decode. The compact declarations keep every occurrence in the
original frame traversal order, including repeated identities and shared
hypothesis chains: re-enrolling type binders can affect later metadata decoding.
The public X.HigherMachine.nextStep and nextStepForHost interfaces retain their
full output; FullRuntime uses nextEvent and fetches the rest on demand.

An equality "mentions arithmetic" exactly when its type argument is nat or one
of its sides contains a successor or an arithmetic operator; Services decides
this with the same predicate that selects its arithmetic branch. A comparison
with a ground truth value is decided without the Presburger solver while no
premise is in scope, in BETA and in V1 alike: the solver represents a literal
n by n successors.

The host numbers native identities in creation order at every stop, up to the
native frontier, before it allocates identities of its own. The numbering no
longer depends on which identities a stop happens to decode.

The term store's identity hash contains live identities. Retired UIDs are kept
as exact merged intervals, so rollback removes hash entries without forgetting
which identities have expired. Consecutive retirement histories compress well;
sparse histories can still require multiple intervals. Authorized snapshot and
assignment replay preserve these records. The host bridge reserves ordered
Unique ranges for unseen native UID gaps instead of allocating a host map entry
for every skipped UID. The built-in UniqueT reserves a range in constant time;
observed identities retain native creation order and their existing mapping.

Immutable, already-normal constructor trees can be reused during normalization,
substitution and binding. The cache excludes variables, nominal constants,
indices, lambdas, wildcards and opaque formula symbols; changing successor or
opaque-symbol configuration refreshes it. In particular, binding a variable
does not turn a term that contains that variable into an immutable cached tree.
Equality and export traverse list tails iteratively. Native tests cover a
10,000-element ground list without copying each suffix during binding.
This does not remove recursive limits for raw term-wire import or every
nonground traversal; large service payloads can still require substantial work.

Embedding API
-------------
src/Hol/V1/FullCompiler.hs

    compileFullProgram :: [TermNode] -> TermNode -> Either String FullProgram

Input is the existing typed, converted representation. Use the existing
module loader/type checker first. The compiler preserves clause order and
lambda structure; it does not execute the query during compilation.

src/Hol/V1/FullBytecode.hs

    withRuntimeMetadata kinds types queryTypes program
    validateFullBytecode / serializeFullBytecode / deserializeFullBytecode
    disassembleFull

Attach the program kind/type environments and query types before embedding or
saving a compiled query. Saved metadata restores identities without depending
on pretty-printed terms. queryFromBytecode is a presentation view used for
answer projection, not an execution path.
When embedding a saved artifact, start the application's UniqueM generator at
or above fullUniqueFloor program; fresh host identities must not collide with
identities already stored in its metadata. The standalone runner does this.

src/Hol/V1/FullRuntime.hs

    createSession :: RuntimeEnv -> IORef Bool -> FullProgram -> IO Session
    withSession :: RuntimeEnv -> IORef Bool -> FullProgram -> (Session -> IO a) -> IO a
    nextSolution :: UniqueM m => Session -> ExceptT KernelErr m (Maybe Context)
    closeSession :: Session -> IO ()
    takeSnapshot :: Session -> IO (Either String Snapshot)
    restoreSnapshot :: Session -> Snapshot -> IO (Either String ())
    closeSnapshot :: Snapshot -> IO ()
    setWorkLimit :: Session -> Word64 -> IO (Either String ())
    getWorkLimit :: Session -> IO (Either String Word64)

nextSolution returns one answer or exhaustion and uses RuntimeEnv services;
runFullProgram additionally drives the _Answer callback/continuation protocol.
The Context of an answer binds the query variables. It also binds every other
native variable only when the complete state was exported: with a residual
constraint or disagreement, while debugging, or after the type fallback above.
Hol.V1.Runtime.execRuntime compiles and runs this full engine directly.
Use withSession for IO exception-safe ownership, or explicitly close sessions
and snapshots. ForeignPtr finalizers provide a backstop. Closed handles and
snapshots from another session are rejected. Serialize access to a session;
the host service bridge is not an application-level concurrent session API.

Snapshots own a deep copy of native terms, bindings, continuations, choice
points, delayed equations and host constraint/premise tokens. Restoring one
rewinds logical state and assignments. Unique identities are never recycled.
External IO is not rewound. Pending assignments are checked and retained across
native alternatives until a snapshot restores the earlier assignment state.
The current work-limit setting is configuration and survives restoration.
Snapshots also retain a clause search or backtracking step paused at a batch
boundary. Equality service responses schedule search; errors encountered while
trying its clauses are reported by the subsequent native next call.

RuntimeEnv's _StackRef provides the current native pending path for inspection,
including hypotheses and types. C choice points are lazy, so this view does not
materialize BETA's alternative Stack frames or reproduce its internal IDs.
Use takeSnapshot/restoreSnapshot for state restoration; the native Session API
does not expose arbitrary replacement of BETA's mutable Stack representation.
The legacy runCompiled/CompiledProgram API is only for the first-order fast
path and does not support interactive assignment or snapshots.

Compile-time specialization
---------------------------
Compiler.hs analyzes conjunctions from left to right and lowers them into an
intermediate goal representation before emitting continuation instructions.
For `sigma P\ P = answer, P Houses.`, the successful equality proves that P
names answer; the following dynamic call is emitted as a static CALL answer.
The resulting reachable program passes the first-order validator and selects
version 1 automatically. No option is needed. Named query aliases retain their
bindings in the displayed answer and saved artifacts.

The equality UNIFY and predicate CALL instructions remain in the program.
Predicate bodies are not inlined, so failure checks, clause/answer order and
cut activation boundaries stay intact. A sigma binder receives a distinct
lexical slot, independent of wildcard and outer binder slots. Disjunctions
are analyzed independently; only identical proven aliases survive their join.
An equality later in a conjunction cannot justify an earlier dynamic call.

The analysis only propagates closed named constants established by standard
equality. It does not guess bindings from calls, lambda values, partial
applications or alias chains whose target is still unknown. Custom equality,
dynamic hypotheses, arithmetic and other unsupported reachable code retain
the full engine. This is a conservative optimization, not a decision procedure
for whether an arbitrary higher-order program will happen to run first-order.

Compiler interning and host symbol registration use lookup maps. Source queries
are still compiled separately, including compilation of their required clauses;
there is no persistent compiled-module cache. Artifact replay avoids this
per-query source compilation work.

Ownership and resource limits
-----------------------------
All C and FFI code lives in src/X/. The executors return at answers, service
requests and scheduler batches. Instructions, failed clause trials and failed
choice traversal consume the batch budget, so a long run of rejected candidates
also yields. General equality resume schedules its search rather than scanning
the whole candidate table inside the service response.
At batch boundaries the host explicitly yields to Haskell's scheduler before
checking pending exceptions, so optimized loops also process timer and signal
handlers. Cancellation regressions are compiled with -O2.
The general term engine's normalization/unification/import/export also have a
per-operation work bound:
5,000,000 node visits by default, configurable with a positive setWorkLimit.
Nested operations share the bound. Remaining recursive term traversals,
including raw term-wire import, limit recursion to 8192 levels. Topological
template loading and iterative ground-list equality/export do not impose that
limit on list length. A single term operation remains atomic; batch cancellation
does not promise a fixed Ctrl-C wall-clock latency for every possible term.
Exceeding a resource bound is an explicit execution error, not logical failure;
a caller may raise the work limit and restore an earlier snapshot to retry.

Backtracking reclaims branch arenas. Closing releases all machine state.
The general engine also compacts its term heap, continuation frames and
hypotheses between two goals, once the heap has grown by the size of its
non-program part and by at least 65536 nodes since the previous compaction
(X.HigherMachine.setCollectionStep; heapCount and collections report the
result). The roots are the program, the pending continuations, every choice
point, every disagreement, and every variable or nominal that has been
exported to or imported from the host. Compaction preserves order, so each
choice point still restores a prefix of the same state; a trailed binding is
kept exactly when its variable is still reachable. An unreachable identity is
retired like one discarded by backtracking. Identities known to the host are
never collected, and the host's identity tables still grow with them: a loop
that passes a fresh unbound variable to a host service in every iteration
keeps that variable. A stop that exports the complete state pins every
variable alive at that stop. The first-order engine is unchanged. Snapshots
copy state rather than using persistent sharing. These are memory/performance
limits, not a reason to silently switch interpreters.

Validation
----------
test/smoke.sh runs the existing frontend/runtime suites and all test/v1/*.sh.
The V1 checks cover compiler/artifact roundtrips, replay after source deletion,
strict native execution, services, snapshots, assignment, resource ownership,
malformed wordcode, cancellation and allocation failures. C tests run with
ASan/UBSan and leak detection. Higher-order unification is compared against
BETA on fixed cases and deterministic generated well-scoped terms.

test/v1/conformance.sh runs the 134 existing BETA transcripts through V1 and
compares answers, constraints, diagnostics and interactive command results.
It removes backend banners and debugger inspection screens: the latter expose
the intentionally different native continuation/choice-point representation.
Separate API tests check the snapshot and assignment behavior behind that UI.

Focused native regressions cover static/dynamic fact order, flexible and nominal
local heads, equality fallback, cancellation during failed search and backtracking,
and snapshots taken during a yielded search. Compact frame metadata is compared
with the full bridge, including allocation failures. Identity tests distinguish
retired UIDs from unused gaps and exercise authorized revival, hash deletion and
snapshot restoration. Ground-term tests retain scope, opaque-term and rollback
checks. Artifact tests reject overflowing nested metadata while preserving
arbitrary-precision natural and Presburger values.

Runtime bottlenecks and changes (2026-11-10, KST)
------------------------------------------------
Profiling the version 1 C engine attributed approximately 61% of sampled time
to unification (including inlined helpers) and 25% to template instantiation.
Every candidate clause previously built its entire head before unifying it
with the goal. Direct head matching avoids those temporary application nodes;
internal variable linking avoids an extra representative and trail entry.
Atomic constants need no occurs traversal. Structured assignments still check
for cycles. Separate C-only experiments measured about 13.0 ms before direct
matching, 10.6 ms after matching, and a further 9--11% improvement from internal
variable linking. These probes were not one end-to-end timing series.

The emitted artifact's decimal table previously used the general Haskell Read
parser. For the 1104-word Einstein artifact, isolated decode plus validation
fell from median 0.787 ms / 8,534,320 allocated bytes to 0.179 ms / 2,023,768
bytes. The existing validator still runs, and noncanonical Read syntax remains
accepted through the bounded fallback.

The GHC 9.6.7 Linux executable also waited for the RTS ticker during shutdown.
An empty REPL process took about 10.7 ms. Relinking the same code with a 1 ms
tick reduced it to 1.6 ms, and Einstein replay from 21.1 ms to 17.0 ms before
the VM/loader changes. ppap.cabal therefore sets -with-rtsopts=-V0.001 only on
Linux with GHC <9.8. The timer and 20 ms context-switch interval remain enabled;
the tradeoff is 1000 timer wakeups/sec instead of 100. GHC 9.8+ has an exit-pipe
ticker implementation and keeps its defaults, including the Stack GHC 9.10.3
build. This is a process-exit cost, not additional logical search.

The optimized cancellation probe also exposed an existing scheduling defect:
allowInterrupt alone did not schedule signal/timeout handlers during an
allocation-free native batch loop. Both FFI wrappers now yield to the Haskell
scheduler at batch boundaries before checking exceptions. The -O2 first-order
and full-runtime timeout regressions pass; actual SIGINT terminates both
engines under both GHC versions.

Teyjus's actual Einstein disassembly uses get_list, unify_variable_t and
unify_local_value_t to match lists directly, and execute_name for tail calls
in member/left_of/neighbor. Its compact list/term layout and separate type
registers also differ from Hol's binary application graph. These explain
remaining architectural opportunities; they are not separately quantified
speedups. This fixture has no argument-index switch instructions, and Teyjus
does perform occurs checks: neither missing indexing nor omitted cycle checks
is an established explanation for this benchmark's gap.

After clause-environment optimization (2026-11-10, KST)
------------------------------------------------------
The next bottleneck was eagerly allocating every local variable and then
unifying those fresh variables with existing goal arguments. A head variable's
first occurrence now captures its goal term directly. Subsequent occurrences
still unify; original query slots retain explicit fresh representatives for
answer projection. Empty slots are completed before the clause body starts,
preserving rollback without introducing a separate environment trail. The
saved bytecode format and instruction set are unchanged.

Separate C-only interleaved probes measured 8.90--8.99 ms before this change and
4.55--4.70 ms after it, about 49% less search time. Haskell-side measurements
found only 0.078 ms in duplicate validation and 0.096 ms in answer decoding and
output, so those checks and the presentation code were retained. This change
optimizes the C search engine used by the Haskell application. Teyjus likewise
uses a C simulator, so this does not establish Haskell-versus-OCaml speed.

Repeated the full-process comparison on CPU 0, with two warmups and nine
shuffled measured rounds, including the prior 06dd8ce executable. All ten
routes produced the same complete answer sequence and variable sharing.
Startup, loading, complete search and output are included; builds are excluded.

Automatic Hol replay takes 35.8% less time than the prior executable and 23.2%

Audit repair diagnostics (2026-11-10)
------------------------------------
The audit's costs are addressed selectively without changing equality,
quantifier ordering or flexible-variable scope semantics. In particular, an
unapplied flexible head is not reused unconditionally: the original fresh-head
operation can preserve dependencies that simple aliasing would restrict.
Regression cases retain that distinction and the visible alias/type behavior.

Deterministic probes compare d927675 with these changes:

    100,000 create/restore iterations, identity/history payload capacity:
        original 4,194,304 bytes; current 1,536 bytes.
    Cloning that empty term store, identity/history payload capacity:
        original 4,194,304 bytes; current 512 bytes.
    1,200-element ground-list peeling, retained native heap nodes:
        original 2,169,005; current 9,605.
    10,000-element ground-list peeling:
        current completes with 80,005 nodes.
    512 unrelated global facts before a matching fact:
        candidate descriptors inspected 513 -> 1; choices at answer 1 -> 0.
    64 unrelated local hypotheses before a matching fact:
        facts instantiated 65 -> 1; choices at answer 1 -> 0.

The identity counts exclude allocator overhead and unrelated store buffers;
they are not RSS measurements. Sparse retirement intervals, retained snapshots
and observed host identities can still consume growing space. The ground-list
probe constructs terms natively and peels them by unification; it is not a claim
that arbitrary 10,000-element append queries now run in linear time. Exporting
many bindings to overlapping list tails can still expand them quadratically.

Runtime metadata membership also uses a symbol-identity set. A focused -O2
probe with 800 existing type symbols reduced its three-sample median from
50.130 ms to 1.418 ms. This times metadata enrichment only, not compilation or
query execution. The exact probe sources, counts, commands and limitations are
recorded in example/teyjus/audit-profile.json.

Verification includes GHC 9.6.7 and 9.10.3 optimized builds, all 164 smoke checks,
134 BETA conformance transcripts, 214 native/BETA HOPU cases, ASan/UBSan and
allocation-failure tests. Further focused checks cover nested artifact overflow,
UID creation order, repeated type declarations, snapshots during yielded search
and cancellation in optimized first-order and general loops.

Host stops, clause exclusion and compaction (2026-11-11)
--------------------------------------------------------
Measured against 430f7a4 built from `git archive HEAD`, on the same Core Ultra
9 275HX machine under WSL2 with GHC 9.6.7. Both executables use the default
`cabal build ppap` flags, not the optimized wrapper of the sections above, so
these numbers are not comparable with the earlier Einstein tables. Each sample
is one fresh process through `V1 --test --general`; elapsed time and peak RSS
include startup, loading, type checking, query compilation, the complete
search and output. A watchdog killed any process above 3 GiB.

The probe is a conversion checker for a small dependent calculus written with
higher-order abstract syntax, with these helpers (the complete source and the
exact queries are in example/teyjus/service-results.json):

    num 0 zero.
    num N (succ M) :- N > 0, K is N - 1, num K M.
    cnt zero.
    cnt (succ M) :- 5 > 0, K is 3 - 1, cnt M.

`num N` makes 2N arithmetic requests on literals up to N. `cnt` walks a unary
numeral of 10000 and makes 20000 requests on small literals. `conv NxN`
checks `mul N N` against the unary numeral N*N by weak-head reduction and
makes no service request.

The num 400 baseline was stopped by a 124-second limit; larger baseline sizes
were not run. BETA takes 0.03 s, 2.06 s and 51.98 s on num 100, 400 and 1000
(18, 44 and 206 MB) at 430f7a4, and 0.03 s, 2.44 s and 50.71 s now; before
this work BETA took 7.75 s and 3034 MB on conv 10x10 and was stopped at
23462 MB on conv 20x20, and those two runs were not repeated.

Where the cost was. At every service request and every answer the host
received each native variable with its fully dereferenced value. On num, the
k-th request therefore exported a chain of k successors once per variable of
the chain, and the export normalized each value into a fresh copy on the
native heap. With the reduced host stops in place and the search engine still
unchanged, an instrumented run of conv 60x60 attributed 9,322,736 of
10,682,909 allocated nodes to clause instantiation: every candidate clause
was instantiated completely, one binder at a time, before its head was
unified. It ended with 3,600 choice points, left by calls whose remaining
clauses had a different constructor in an argument; nothing below a choice
point can be reclaimed. With exclusion and head-first instantiation, and
still without compaction, the same run allocated 1,874,927 nodes and ended
with one choice point. A comparison of the
literal 2,000,000 with 0 took 0.14 s and 122 MB because the Presburger term of
a literal is unary; the ground shortcut makes it 0.02 s and 20 MB.

Forced-general Einstein (`sigma P\ P = answer, P Houses.`, source, five
alternating runs): 1.69--1.73 s (median 1.72 s) and 291 MB before, 0.36--0.37 s
(median 0.37 s) and 30 MB now. The two transcripts are identical. This is the
default build; the optimized-wrapper and bytecode-replay measurements of the
earlier sections were not repeated, and no Teyjus comparison was made.

Over the 134 BETA transcripts run through `V1 --test --general` (236 sessions,
2,879 service events), temporary counters recorded 291 complete-state exports,
378 root-state exports for requests and 139 for answers. The other events were
answered from their terms. A stop that falls back is counted in both groups.

What these numbers do not show. They are single samples of one probe and one
puzzle, not a benchmark of higher-order unification. num and cnt still grow
with the number of iterations (about 1.4 kB per num iteration at 100000):
each iteration exports one fresh unbound variable, which stays pinned natively
and in the host's identity tables. A program that leaves a host constraint or
an arithmetic premise in force exports the complete state at every stop, as
before, and compaction then finds every variable pinned. Binding a variable to
a term that contains lambdas, nominals or variables still rebuilds that term,
and unification still normalizes both sides at every level. The comparison
shortcut does not change the unary representation inside the solver: a
comparison that is not ground, or that has a premise in scope, still costs
time proportional to its literals.

Validation: 164 smoke cases; the 134 BETA transcripts through the forced
general engine for 430f7a4, for this revision, and for this revision with a
compaction before every goal; every native C scenario twice, the second time
with a compaction before every goal, under ASan/UBSan with leak detection and
74 allocation-failure points. New regressions: exclusion order and choice
points, a 20000-call descent whose heap stays within 4096 nodes of the
program, 9000 arithmetic requests that decode at most their own variables and
replay from a snapshot across compactions, and a 300000-call descent bounded
below 200000 heap nodes. The yield_failed_backtracking fixture now uses an
alternative clause that matches and fails in its body: its former alternative
`p red` is excluded and no longer creates the choice points the test walks.
